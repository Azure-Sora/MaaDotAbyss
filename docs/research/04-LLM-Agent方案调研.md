# 04 · LLM GUI Agent 方案调研

> 调研日期：2026-08-29

## 1. 结论先行

1. "截图 → 多模态大模型决策 → 注入点击"的范式已被多个项目验证，**放置类游戏（无即时性要求）是该范式的最佳适用场景**。
2. 不建议复用通用 Agent 框架（codex CLI 等）的核心——它们是终端/编码向的，GUI 操控循环本身只有几百行，自研最可控。**自研轻量 Agent 循环 + OpenAI 兼容视觉 API** 是最优解。
3. 你提出的"任务即回合、完成即裁剪上下文"思路方向正确，本方案在其上补四块：**任务知识卡、完成验证分离、锚点自动沉淀、确定性等待**。

## 2. 现有轮子盘点

| 项目/模型 | 形态 | 可复用度 |
| --- | --- | --- |
| [UI-TARS / Agent TARS](https://github.com/bytedance/ui-tars-desktop)（字节） | 开源 GUI Agent 栈（模型 + Electron 桌面端），动作空间设计成熟 | 借鉴动作空间与 prompt 设计；整套偏 Web/桌面通用，重 |
| Lumine（字节 Seed，《原神》通用 Agent，Qwen2-VL-7B 微调） | 研究项目，3D 开放世界实时感知决策 | 证明范式可行；不可直接复用（微调模型） |
| [Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM)（智谱） | 手机端 ADB 控制的多模态助理 | "截图→理解→操作"同范式，可参考其提示词 |
| Claude computer use / OpenAI CUA / Gemini computer use | 闭源 API，模型直接输出坐标动作 | API 可选，价格高，留作兜底 |
| codex CLI（开源） | 终端编码 Agent（Rust） | 仅借鉴"工具循环+上下文管理"思想，代码不可复用（领域不同） |

## 3. 推荐架构：自研轻量循环

```
任务清单 tasks.yaml ──→ Runner（编排/看门狗/通知）
                          │ 逐任务派发
                          ▼
                    Episode 循环（每任务一轮）
        ┌────────────────────────────────────────┐
        │ 1. 载入任务知识卡（无则进入探索模式）          │
        │ 2. 截图(MAA) → 组装上下文 → VLM 决策         │
        │ 3. 解析 JSON 动作 → MAA 执行 → 等待/帧差检测  │
        │ 4. 模型自报完成 → 验证器复核 → 通过/打回       │
        │ 5. 通过：写回知识卡+存锚点图 → 上下文清空       │
        └────────────────────────────────────────┘
```

动作空间（对齐 UI-TARS，够用且小）：

```json
{"action": "click|double_click|right_click|drag|key|scroll|wait", ...坐标/键名/时长...}
{"action": "report", "status": "done|failed|blocked", "exit_condition": "画面上出现『关卡选择』横幅"}
```

模型接口抽象：OpenAI 兼容 Chat Completions + image_url，`base_url/model/api_key` 全配置化——任何模型即插即换。

## 4. 对你原始思路的评估与增强

### 4.1 你提出的上下文管理（✔ 成立，需两点补充）

> "摸索过程中产生的多轮交互，在任务完成后从上下文中剔除，只保留任务定义 + 已完成 + 下一任务。"

- **正确**：这就是 episode 化的上下文管理，避免长会话漂移和 token 爆炸。
- **补充 1（知识卡）**：探索 transcript 不该扔掉就完事——让模型在通过时顺手压缩出 3~5 条"路径要点/坑"写进该任务的知识卡（YAML/MD）。下次运行同一任务**直接带着卡片走短路径**，一次探索、终身受惠。对单人维护的项目，这是把"打标成本"转嫁给模型本身。
- **补充 2（验证分离）**：不能只信模型自报"我成功了"。要求模型在 report 时**先声明退出条件**（完成时长什么样），框架再取一张新截图、单独发一次"仅验证"请求（便宜、可并发、可换便宜模型）。验证失败就把任务打回重试。

### 4.2 锚点自动沉淀（零人工打标的图像库）

每次验证通过的瞬间，把该帧截图按 `tasks/<name>/anchor_<n>.png` 自动归档。日积月累得到一套**自动打标的关卡锚点图**：
- 供验证器做低成本初筛（感知哈希/模板匹配，不花 token）；
- 将来如果某些路径想固化成 MAA pipeline 模板节点，图片素材已经现成。

### 4.3 确定性等待（最大的省钱点）

挂自动战斗、加载、传送读条这类"纯等待"，**不该让 LLM 每秒看图**：
- 帧差检测：连续 N 帧无显著变化 → 状态稳定，交给 LLM 判断一次即可；
- 或知识卡里声明 `wait_for: 静止窗口/特定锚点`，Runner 直接休眠轮询。

预计等待类时间占日常流程 >60%，全部走确定性路径后 LLM 调用次数能降一个数量级。

### 4.4 看门狗（无人值守的底线）

- 单任务步数上限 / 单步超时 / 检测连续 K 次动作后画面无变化 → 判卡死；
- 全程截图留档（滚动清理），失败自动保留现场 + 通知（邮件/Telegram/Windows 通知）；
- 每日预算上限（token / 调用次数）。

## 5. 模型选型与成本测算

| 候选 | 定位 | 价格量级（2026-08 查证） |
| --- | --- | --- |
| **MiMo-V2.5（小米，★ 已选为主力）** | 原生全模态（图像/视频/音频/文本），1M 上下文，MIT 开源可自部署 | 订阅制 ¥39/月（4.1B credits）；按量约 $1/M 输入、$3/M 输出（[定价页](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)） |
| GLM-4.6V-Flash（智谱） | 免费备选档 | 0 |
| GLM-4.5V | 备选，视觉推理强、中文 UI 识别好 | 输入 $0.6/M、输出 $1.8/M（[官方](https://docs.z.ai/guides/overview/pricing)） |
| Qwen3-VL 系列 | 备选；未来本地部署候选（用户高性能 PC 可用后） | 同量级 |
| GPT / Claude / Gemini 旗舰 | 困难场景复核或兜底 | 高一个数量级 |

- **MiMo-V2.5 接口形态（已确认）**：官方声明兼容 OpenAI 与 Anthropic 协议，模型原生理解图像——我们的 OpenAI 兼容抽象层可直接对接；base_url、图像传参细节在 M0 接入时按 [官方文档](https://mimo.mi.com/docs/zh-CN/quickstart) 核对。
- 后续本地化路线：用户另一台高性能 PC 就绪后，可经 vLLM/llama.cpp 起 OpenAI 兼容服务跑开源多模态模型（Qwen3 系 / MiMo 开源权重），抽象层零改动切换。

**测算**：720p 截图 ≈ 1.1k tokens；一次日常 ≈ 200~600 个决策步（知识卡成熟后大幅减少）；每步上下文 ~1.5-3k tokens。
→ MiMo 订阅档或 GLM-4.5V 下每天约 **¥0.3~1**；**成本完全不是约束**，瓶颈只剩时延（1.5~5s/步，放置游戏无感）。
