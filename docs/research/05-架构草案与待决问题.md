## 0. 已定决策

| 决策点 | 结论 |
| --- | --- |
| 语言栈 | **Python**（MAA 官方绑定 + LLM 生态；子会话部分用 ctypes/comtypes 移植，代码量小） |
| LLM 主力 | **小米 MiMo-V2.5**（OpenAI/Anthropic 双协议兼容，原生图像理解；按量 $1/M-in、$3/M-out）。base_url `https://api.xiaomimimo.com/v1`（按量通道，key 前缀 `sk-`；订阅通道为 `token-plan-cn`）。后续在高性能 PC 上本地部署开源多模态模型作为备选路线 |
| 后台策略 | **前台先跑通**：M0~M2 按前台最稳路径推进，M3 再做后台（普通后台 PostMessage/AnchoredTouch 实测 → 不行则子会话分身） |
| 使用形态 | **CLI + YAML 配置起步**，GUI 留到 M4 |
| 通知渠道 | **Windows 系统通知** |
| 仓库 | **计划公开** → 代码不得含个人路径/账号信息；密钥只放 `.local/`（已 gitignore）；含账号的截图不入库 |

环境事实：游戏窗口已由用户固定 **720P（1280×720）**，游戏已开启可测试；MiMo API Key 就位于 `.local/mimokey.txt`。

## 1. 总体架构（草案）

```
┌────────────────────────────────────────────────────────────┐
│ Runner（Python）                                            │
│  tasks.yaml 任务清单 → 调度 → 看门狗 → Windows 通知            │
└──────┬─────────────────────────────────────────────────────┘
       │ Episode（每任务一轮，上下文互不污染）
       ▼
┌──────────────┐   截图/点击/滑动/按键    ┌─────────────────────┐
│ Agent Loop    │ ────────────────────→ │ MAA 设备层            │
│ 上下文组装     │ ←──────────────────── │ Win32Controller       │
│ 动作解析/执行  │        帧图像           │ 前台期: ScreenDC+Seize │
│ 验证调度      │                        │ 后台期: FramePool+Post │
└──┬─────────┬──┘                        └─────────────────────┘
   │         │
   ▼         ▼
┌────────┐ ┌──────────────────────────┐
│ MiMo API│ │ Memory（本地文件）         │
│ OpenAI  │ │ tasks/<n>/knowledge.yaml │  ← 知识卡（探索结论）
│ 兼容接口 │ │ tasks/<n>/anchor_*.png   │  ← 自动沉淀锚点图
└────────┘ │ runs/<date>/*.png+log    │  ← 运行留档
           └──────────────────────────┘
```

## 4. 风险清单

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| **IP 防御 403 → 游戏不可用** | 中 | **绝不自动重启游戏**（见 §6 工具铁律）；检测到 403 立即停止 + Windows 通知，人工换 IP 重进 |
| **窗口最小化 → 截图全黑**（M0 实测，伪最小化救不了） | 中 | Runner 启动检查 IsIconic 并恢复；任务期间禁止最小化，遮挡可接受（FramePool 抗遮挡） |
| **消息注入输入彻底无效**（M0 复测：Unity 旧 Input 轮询硬件状态，不读消息队列，前台也点不动） | 高（对后台目标） | M1~M2 前台 Seize 模式不受影响；M3 真后台走**子会话分身**（首选）或 **BepInEx 桥**（备选） |
| 游戏偶发"加载中卡住"（手动点击也无反应） | 低 | 帧差骤降=卡 loading 信号；点右上角菜单按钮加速恢复；勿与 403 混淆、勿重启游戏 |
| VLM 误报完成 | 中 | 验证分离 + 锚点哈希初筛 |
| 游戏更新改 UI | 低 | LLM 方案天然抗变化；知识卡失效时自动重探索 |
| 游戏窗口分辨率/位置漂移 | 低 | 用户已固定 720P；启动时校验窗口尺寸与位置 |
| 同进程多控制器 segfault（M0 实测） | 低 | 架构约定：一个进程一个控制器 |

## 6. 游戏启动与 403 约束（重要）

- 开服期机器人号泛滥，游戏 IP 防御严格：DMMGP 启动后需**多次尝试不同日本 IP** 才能进入。
- 游戏内一旦报 **403**，只能人工重新走启动流程。
- **工具铁律**：
  1. 绝不自动关闭/重启游戏或其进程；
  2. 只绑定"已在运行的窗口"，启动环节不属于工具职责；
  3. 检测到 403/异常弹窗 → 立即停止当前任务链 + Windows 通知，等待人工接手；
  4. **R18 禁区**：抽卡页面与角色亲密度页面永不点击/进入（任务设计排除 + Agent 提示词禁页 + 误入立即退出）；入档截图必须为主页/常规功能页。
