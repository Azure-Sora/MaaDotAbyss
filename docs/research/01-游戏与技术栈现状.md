## 2. 引擎与技术栈（本地文件实证）

- **Unity 引擎 + IL2CPP**：`UnityPlayer.dll`、`GameAssembly.dll`（IL2CPP 产物）、`UnityCrashHandler64.exe`、`baselib.dll`。
- **渲染**：D3D12（存在 `D3D12` 目录）。
- **UI 方案**：uGUI（`UnityEngine.UI.dll`）+ TextMeshPro + EnhancedScroller。
- **输入方案**：仅有 `UnityEngine.InputLegacyModule`（旧版 Input Manager），**未发现新 InputSystem 程序集**。这对后台消息注入是利好（旧输入走窗口消息队列的可能性大）。
- 其他：Live2D Cubism、CRIWARE（音频/视频）、Arbor（可视化脚本）、Behavior Designer、DOTween、UniTask、MessagePack/MessagePipe、Firebase、Adjust SDK、NoaDebugger。
- 依据：`BepInEx/interop/` 下共 199 个由 IL2CPP 生成的 interop 程序集，可直接 grep 确认依赖。

## 3. 已存在的注入环境（重要现状）

游戏目录中已经装好并运行着 **BepInEx 6 (IL2CPP 分支)**：

- `winhttp.dll`（Doorstop 代理）+ `doorstop_config.ini`（enabled=true，加载 `BepInEx\core\BepInEx.Unity.IL2CPP.dll`）
- `BepInEx/interop/` 已生成完整 interop 程序集（说明 preloader 已成功跑过）
- `BepInEx/plugins/AbyssMod/`：**社区汉化 Mod**（[anosu/dotabyss-translation](https://github.com/anosu/dotabyss-translation) 的客户端），版本 1.0.6，加载了 zh_Hans 静态翻译包（1 万+ 条目）与自定义字体
- `BepInEx/LogOutput.log` 显示 Chainloader 正常完成，无报错

**含义**：

1. 注入链路在此游戏上是稳定可用的 → 将来若需要"确定性的游戏内桥接"（BepInEx 插件直接读写游戏状态、直接调用 uGUI 按钮），**技术通道已验证存在**，可作为 LLM 视觉路线的兜底/增强，不需要动游戏本体。
2. 没有发现任何反作弊拦截注入的迹象（单机向放置游戏，符合预期）。

## 4. 对自动化方案的影响

| 关注点 | 评估 |
| --- | --- |
| 反作弊 | 未发现；BepInEx 常驻运行无恙。风险低（待长期观察） |
| 后台消息输入（PostMessage） | 旧 Input + uGUI，大概率接受窗口消息点击，**M0 实测**（Unity 有的游戏会在失焦时丢弃/暂停输入） |
| 后台截图 | Unity + D3D12：PrintWindow 兼容性一般，WGC FramePool 应该可用（窗口被遮挡时可用，最小化需伪最小化），**M0 实测** |
| 窗口绑定 | 窗口标题应为 `ドットアビスX`（M0 实测确认），用 `Toolkit.find_desktop_windows()` 按标题/进程过滤 |
| 分辨率 | **用户已固定 720P（1280×720）**，坐标系稳定 |
| 启动方式 | **必须经 DMM Game Player + 日本 IP（开服期 IP 防御严格，常需多次换 IP）；游戏内 403 只能人工重开——工具绝不自动重启游戏，检测到 403 即停止并通知**（详见 05 文档 §6） |
| 界面语言 | 汉化后为中文，对多模态大模型识别非常友好 |
| 玩法节奏 | 战斗全程可挂自动，日常=点 UI + 等待。**对 LLM 决策时延（1~5 秒/步）完全不敏感**，这正是 LLM Agent 方案可行的根本原因 |

## 5. 实测结果（M0 已完成，详见 [06-M0-POC记录](06-M0-POC记录.md)）

1. ~~PostMessage / SendMessage 系输入~~ **❌ 失效**：Unity 焦点门控，失焦时忽略所有鼠标消息（伪造 WM_ACTIVATE 也不行）；真后台需子会话或 BepInEx 桥。
2. ~~后台截图~~ **✅ FramePool(WGC) 在失焦/遮挡下稳定出图**；但**最小化时全黑**（引擎停渲染），窗口可遮挡不可最小化；ScreenDC 抗遮挡差（后台禁用）。
3. **✅ 窗口**：`UnityWndClass` / `ドットアビスX` / 1280×720；同进程只能建一个 MAA 控制器（多建 segfault）。
4. ~~直接启动 exe~~ 已确认：启动必须由人工经 DMMGP + 日本 IP 完成，工具不负责启动游戏（见 05 文档 §6）。
5. **✅ 失焦时主循环持续运行**（帧差~14%/1.5s）→ 等待类场景用帧差检测，无需 LLM 轮询。
