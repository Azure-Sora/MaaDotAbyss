# 12 · 深渊自动刷装备设计

> 2026-08-29 ｜ 用户提议，讨论定稿 ｜ v4：并入答疑二轮（中断/帰還、事件强制选择、蓝紫 Combo 精确机制、倍率弹窗）+ 商店/倍率截图 ｜ 状态：设计已对齐，**先勘探后实施**

## 0. 一句话

深渊 roguelike 的自动化：**模型当眼睛、代码当大脑、剧本当手脚**。LLM 只做识读（事件文本/buff 弹窗/异常画面），纯 Python 规划器持整局账本做全部战略决策，执行层复用设备+锚点剧本。用户开局配置"四色配额 + 目标层数"，工具忠实执行。

## 1. 为什么不照搬现有两种模式

- **剧本模式不行**：每把地图随机，无固定路径可录；
- **纯 LLM 不行**：30~50 层 × 每层 2~3 个决策点 ≈ 上百次决策。模型历史被 `HISTORY_KEEP` 截断，决策漂移；且贵、慢、不可单测。

三权分立：

| 层 | 谁来做 | 干什么 |
| --- | --- | --- |
| 识读 | 模板匹配为主 + LLM 兜底 | 读**固定**的：房间图标/标签、候选箭头、HUD 数字；LLM 读**多变**的：事件文本、buff 弹窗、异常画面 |
| 规划 | 纯 Python | 整局账本在手：选房、选 buff、回复房三选一、事件拍板、续行/停手。确定性、零成本、可单测 |
| 执行 | device + 锚点 | 进房点击、AUTO 挂机、`wait_stable`、收结算——与日常任务共享 |

## 2. 游戏机制规格（用户口述 + 实测，2026-08-29）

- 地图：类杀戮尖塔，**竖向自动跟随**（可见当前层+下两层），**横向超出屏幕需拖动**；房间七类（戦闘/強敵/ボス/回復/イベント/ショップ/宝物）；地图标签已见 **戦闘/強敵/回復/イベント/商店**（商店为汉字），宝物标签未采到（出现率低，LLM 兜底）；道路非全连接；
- **候选标记已确认**（用户答疑）：房间上的紫色箭头和房间边上的**光圈** = 该房间当前可进入；
- **推奨戦力不用管**（用户答疑）：水分很大，推奨远高于総合戦力也轻松过关 → 房间战力数字一律不读、不做风险闸门；
- **HP 不做常规读取**（用户答疑 v2）：战斗内基本回满，唯一死法是战斗外被事件扣血归零；但事件**不能一刀切禁选 HP 负收益**（有纯负面事件，更多是"扣少量 HP 换减侵蚀"的划算项）→ 改用**战斗间 HP 预算制**（§6）；
- **侵蚀机制精确版**（用户答疑 v2）：进房默认 +5；**5 蓝码 Combo：侵蚀上升 −5**（进房净 0）；另有单个蓝码同效果，两者齐备进房**倒扣**侵蚀；紫码对称反向 → 侵蚀完全可控；实测：51 层侵蚀 0（蓝 build）、30 层 15；
- 每把**起始层**由科技树决定（用户当前从 20 层开始）→ 目标层数用绝对层数表达；
- 深渊代码：红黄蓝紫四色，组名**インパクト(黄)/ラッシュ(红)/セーフ(蓝)/リスク(紫)**，按冲突对分两栏；总携带上限可见（0/**31**）；精英/Boss/部分事件获得，弹窗 **N 选 1**，**选项卡自带战力增量**（同色 tiebreak 用）；有**リロール**（有限次）和**受け取らない**（放弃）；同色凑数有套装效果；红黄、蓝紫互斥；
- 侵蚀到 100 强制失败；回复房**三选一**：浄化（-30）/ 休憩（HP+30%）/ 変換（换码）；事件选项带**机械化效果标签**（绿=收益、橙=消耗；实测"侵食率+40 换一个代码"）；
- **两种钥匙**（实测厘清）：**ナノの鍵**（宝箱用，地图顶栏显示，实测 0）≠ **ゲットキー**（boss 后续行用，探索続行確認界面显示所持，实测 **120 个，管够**）；
- **宝箱房=垃圾**（用户答疑）：收益很低 → 权重垫底绕开；实测开箱 UI（「宝箱を開ける方法を選択」）三选价：**消耗钥匙 -1 / HP -40% / 浸食 +40**（確定 + X）——被迫进入时先试 X（能否不开离开待实测），必须选则**浸食+40**（绝不 HP-40%、不花钥匙）；地图标签实测=「宝箱」；
- 商店（V1 跳过）：覆盖层右上自带 鍵/コイン HUD；**卖代码**（硬化躯体·改 100 コイン、深淵化身·真 150）→ V2 买码路线的素材；
- 每 10 层 Boss → **探索続行確認**（次のフロア N + 浸食率 + 所持ゲットキー，按钮 **中断する/帰還する/続行する**；**中断=暂时退出深渊、下次进来原地续跑；帰還=就此撤退结算**——已确认）；続行 → **ゲットキー消費弹窗**（倍率 1/3 档滑条，默认 1 倍直接**使用**；倍率作用于下 10 层的分数/掉落，>1 倍 1日1回限定）→ **安全箱**（拠点に送る，失败也保留）→ **直接キャンセル**（用户指示没用）→ 回地图；
- **结算规则**（用户答疑）：帰還する 与打到底**报酬完全相同**（目标层数只为省时，无收益梯度）；中途暴毙（HP 归零/侵蚀 100）**血本无归** → 全部策略保守化的依据；
- 战斗/精英/Boss 挂自动足以通关；**刷装备目标：精英/Boss 为主**。

- **兜底（MAA 后端）**：原候选制+分节扫读降级为无桥时的备用，逻辑保留在 `abyss.read_candidates_anchors`。

### 4.2 兜底细化：分节扫读（MAA 后端用，结构化合并不做像素拼接）

仅在候选缺失/被屏幕边缘裁切时启用。**已实测验证（2026-08-29，poc/abyss_swipe_test2，真机深渊地图）**：

- `swipe()`（MAA `post_swipe`，Seize）拖深渊地图**有效**：600px 鼠标位移 → ~432px 地图位移，**灵敏度 ≈0.72**，纵向零漂移；
- **松手不弹回**（2s 后位移 0.0），镜头位置持久；
- 到边判停用 **phaseCorrelate**——不能用 `diff_ratio`（雾气/光柱常驻动画使原始帧差永不归零），实测到边时 dx=0.0 判定干净；
- 实测该层地图总宽 ≈ 2.4 屏（起点最右，西向共扫出 ~1209px）。

每节独立检测房间 → 相邻节按相位位移去重合并**检测结果**（非图像拼接）。

## 5. run 控制循环

```
入场（科技树起始层）→ 現在地へ → 读候选
循环：
  规划器选下一间房（候选贪心：价值−侵蚀代价）
  点击房间节点进入
  对账：OCR 浸食率/层数（buff 弹窗时顺带核对 所持数 x/31）
  按类型解决：
    戦闘/強敵/ボス → AUTO/倍速锚点 → wait_stable → 收结算
    回復 → 规划器三选一（侵蚀≥安全线→浄化；HP 账本低→休憩；默认浄化）
    イベント → LLM 读效果标签 → 规划器拍板（**X 不可跳过、必须选一项**；侵蚀服从预算；HP 扣血走战斗间预算）
    ショップ → X/退出（勘探确认退出方式）
    宝物 → 权重垫底基本不进；被迫进入用侵蚀开
    buff 弹窗 → 四色图标模板 + 战力数字（LLM 一次读 JSON）→ 规划器选色/リロール/受け取らない
每 10 层 Boss 后（探索続行確認）：
  未到目标 → 続行する → 倍率弹窗（默认 1 倍，点前核验）→ 使用 → 安全箱 → キャンセル → 回地图
  到目标 → 帰還する（就此结算；中断する=挂起可续跑，V2 可做"暂停深渊"）→ 结构化轨迹落盘（路径+每步决策理由）
```

## 6. 规划器（纯代码，可单测）

**账本**：`erosion / getkeys / coins / hp(粗账,仅事件联动) / buffs{黄,红,蓝,紫} / quota / carry_cap(31) / target_floor / floor`。

**规则**：
- **侵蚀动力学**：进房 +5；5 蓝码 Combo −5，另一同效果蓝码再 −5（齐备进房净负）；紫码反向。账本以 HUD 实测为准，公式仅用于规划器余量预估；
- 选房：候选中 `value` 最大。基准权重強敵 > イベント > 戦闘 > 宝物≈ショップ(0)；回復动态价值（侵蚀 ≥ 安全线飙升，安全线默认从宽如 80）；侵蚀投影 ≤ 100 − 余量；
- buff：配额缺口最大的色优先 → 同色内战力增量最高；冲突对/上限硬约束；全满 → 受け取らない；全冲突色 → リロール（有余量）再放弃；**蓝码兼具侵蚀控制价值**，深跑时蓝配额优先级内置加权；
- 回復房：默认浄化；休憩仅当 HP 粗账偏低；
- 事件（**强制选择**）：先过滤——自上次战斗累计 HP 扣减 ≤ 预算%（默认 30%，战斗后清零，战斗基本回满）；通过过滤后按 收益 > 零成本 > 侵蚀代价 排序；全超预算选代价最小项（先保 HP 再看侵蚀）；纯负面事件同样走此排序；
- Boss 后：`floor < target` → 続行する（倍率默认 1 倍直接使用）；否则 帰還する（结算撤退）；
- 数值常量全进配置，勘探实测校准。

## 7. 识读层

- 候选：箭头/光圈模板 matchTemplate；房间分类：七类小模板，低置信批量 LLM；
- HUD：浸食率/层数/ゲットキー固定位置 OCR；探索続行確認界面数值又大又清晰，是每 10 层的天然对账点；
- 事件/buff 弹窗：LLM 一次读成结构化 JSON（`read_json_from_image` 模式）；
- 原则：**账本为主、HUD 为准、随时可重读**；失配挂起重读，连续失配停下问用户——复用教学模式（doc 11）的 ask_user/手动接管通道；
- 覆盖层（回復/イベント/ショップ）是半透明的，锚点只取覆盖层自有元素（标题/选项卡边框/確定/キャンセル）。

## 8. 执行层

- `swipe()` 已落地 `device.py` 并真机实测可用（数据见 §4.2）；
- 战斗序列复用日常任务 AUTO/倍速锚点 + `wait_stable`；
- Boss 续行四连：続行する锚点 → 倍率弹窗「使用」锚点（**点前核验倍率显示 =1**，防持久化误花钥匙）→ 安全箱「キャンセル」锚点 → 回地图 `wait_settled`；
- 403/blocked 沿用现有处理；战斗疑似失败/看门狗触发 → 挂起问用户。

## 13. 实战验证战报（2026-08-30，桥后端，真机 run）

- **事件房闭环**：野兽事件（特殊战斗/浸食+10/花30币）——选项卡与確定均可射线点击；事件内置战斗不再多计层数（进房即+1）；

- **HUD 对账**（零 OCR）：`UICanvas` 下 StageName（层数）/Gauge_Abyss/Value（侵蚀）/Key|Coin 的 Body/Value——实测侵蚀每层+5、战斗奖励金币入账，全部与账本吻合；

- **剩余待实测**：回复房三选一覆盖层、商店 X、宝箱 X 语义、Boss 层续行四连、代码满仓行为。

## 14. 2026-09 版弹窗变更实测（スキップ確認 + 倍率弹窗新 UI）

游戏版本更新后入场/续行流在倍率弹窗**之前**多一个新弹窗，倍率弹窗本身也改版：

- **スキップ確認**（`Popup_Confirm_NetherSkip(Clone)`，挂在 `Front/PopupService/NormalRoot`）：
  三选项 **行わない/スキップ/レアスキップ** = `Button_Cancel/Skip/RareSkip`（Popup_ButtonSet3）。
  スキップ=耗票直跳 10 层、レアスキップ 更强，但「ゲートキーの消費倍率は1に固定」——
  **固定 行わない（不跳过，用户指示）**，否则少拿倍率收益。`_skip_confirm_decline` 处理，
  已真机点掉验证；入场流在 出撃 前后各查一次（编成页一到就可能弹），续行流在 続行する 后查。
- **倍率弹窗改版**：倍率数值与『倍』单位**分属两节点**（数值=名为 `Value` 的节点紧贴『倍』左侧，
  包围盒略重叠），旧正则 `[123]\s*倍` 整文本匹配**落空 → 1 倍核验形同虚设**；
  弹窗文案 ゲットキー→**ゲートキー**，旧 `has_popup` 检测同样失明。`_multipliers()` 兼容

### 14.2 战斗房稀有掉码 + 结算转场卡 LOADING（2026-09-01 实战修复）

### 14.3 QUEST CLEAR 卡死：树爆炸截断 + 事件内置战斗无结算流（2026-09-01 实战修复）

事件房触发内置战斗，打完掉码、选码成功后卡死在 QUEST CLEAR 页 → no_candidates。两根因：

- **树爆炸截断（max_nodes 坑正式落地）**：QUEST CLEAR 页树上挂着图鉴缩略图按钮组
  （Thumbnail_ContentAll/Waiting/Button 重复数百个），`ui_tree(max_nodes=12000)` 截断把
  Button_Next 所在的 UICanvas 整个切掉——_result_step 找不到按钮 → 退化左上角 (0,0)，
  命中的是 TutorialFocus/Mask/ScreenMask（教程遮罩，点了无效）→ 页面推不走。
  修复=**abyss.py 全树读统一 30000（22 处）**，与 doc 14 既有教训并轨；实机验证 30000
  下 Button_Next 一发命中、QUEST CLEAR 推走回图。
- **事件内置战斗没有正式结算流**：_resolve_event 点完確定直接 return，内置战斗的结算
  全靠 _wait_map_stable 兜底——而它 (a) 调 _result_step 传 brain=None（未知名永不定色）、

  正式交 resolve_battle；回 Nether（打过/纯文本事件）→ 返回；转场启动有延迟窗，场景短暂

  另 _wait_map_stable 签名加 brain 并由 run_to_floor 透传。

**运维教训：GUI 进程不重启则 abyss.py 修复不生效**（worker 内 `from .abyss import ...`
走 sys.modules 缓存）——本次日志中「→ take」决策与当前 pick_code 逻辑矛盾（全未知色
