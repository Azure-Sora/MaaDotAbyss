# 10 · UI 框架选型调研

> 2026-08-29 ｜ 背景：tkinter 凑合版 GUI（`dotabyss_agent/gui.py`，任务列表+日志+截图预览）已不够用，打算换成正经 UI。本文盘点 MAA 生态的几种 UI 框架，评估哪条路适合本项目。
>
> **已决（2026-08-29 与用户确认）：路线 A（PySide6 + QFluentWidgets），首期范围 MVP 三件套（任务面板 / 实时画面 / 决策流时间线）。已落地：`gui.py` 重写为 FluentWindow 双页（任务 / 监控），`agent.run_task` 与 `runner.run_selected` 增加 `event_cb` 结构化事件钩子。**

## 一句话结论

**MAA 生态的四种"通用 UI"（MFAAvalonia / MFW-CFA / MXU / MWU）全是 interface.json 驱动的发布用启动器，为"资源作者 → 最终用户"的分发场景设计；本项目是不走 PI 协议的 Python 自研 agent loop，UI 要展示的恰恰是 agent 内部过程（LLM 决策流 / 探索录制 / 知识卡 / 剧本锚点），声明式协议表达不了。结论：不搬现成 UI，借它们的"皮"自建——首选 PySide6 + QFluentWidgets（MFW-CFA 同款 Fluent 外观，纯 Python 单栈），次选 FastAPI + Web 前端（MWU/MXU 同思路）。**

## 为什么"通用 UI"不适配我们

三条错位，任何一条单独出现都够劝退：

1. **协议错位**。我们直接用 maa Python 绑定的 `Win32Controller`（`device.py`），设备层以上全是自研代码（agent 循环、双速 flow、flowgen、precondition）。采用任一通用 UI = 把项目重构成 PI V2 资源项目：写 interface.json、把逻辑拆成 agent 子进程/自定义识别动作——纯迁移成本，核心体验零增益。
2. **表达力错位**。通用 UI 的界面范围 = 任务列表 + 选项设置 + 日志/进度 + 通知。我们要的核心页面——每步截图+思考+动作的**决策流时间线**、探索录制后的**剧本/锚点审核**、知识卡管理、运行历史回放——声明式协议表达不了。MFAAvalonia 与 MXU 的 README 都明确排除了嵌入自定义界面的可能。
3. **收益错位**。通用 UI 白送的是定时任务、通知推送（钉钉/飞书/TG…）、Mirror酱更新器——那是"发给几百个陌生用户"才需要的东西，单人自用一件都用不上。

反过来说，通用 UI 唯一的正确打开时机是：将来真要把工具发布给非开发者用，届时再做 PI V2 化，把通用 UI 当"发布壳"。

| 页面 | 数据源/接口 | 现状 |

## 三条候选路线

| 维度 | A. PySide6 + QFluentWidgets（推荐） | B. FastAPI + Web 前端（MWU/MXU 思路） | C. 通用 UI（MFAAvalonia / MFW-CFA） |
| --- | --- | --- | --- |
| 与现有代码集成 | 直接 import，进程内调用，`log/frame_cb/stop_event` 原样接 | 后端直调同样容易，但要加 HTTP/SSE 一层 | 需 PI V2 重构 + agent 化，最大 |
| 决策流等富交互 | 够用；QWidget 做时间线/图集比 web 略费劲，单人自用无碍 | web 做富交互最顺手（MDN 级排版、图片网格、缩放） | 表达不了，致命 |
| 新增技术栈 | 无（纯 Python，仅加 PySide6 + 一个组件库） | 前端工具链（Vue/React + pnpm + 构建），双语言 | C#/Avalonia 或整个 PI 生态 |
| 打包 | PyInstaller/Nuitka 单 exe，成熟 | 要么开本地服务开浏览器，要么 pywebview/Tauri 壳 | MFW 用 Nuitka 已验证可行；MFAAvalonia 需 .NET |
| MAA 风格还原 | 高（QFluentWidgets 就是 MFW-CFA 在用的 Fluent 组件库） | 高（自己写，自由度最大） | 即装即得 |
| 许可注意 | PySide6 LGPL（动态链接合规即可）；PyQt-Fluent-Widgets 免费版 GPL-3.0，商用需 Pro——自用无碍 | 自写无碍；fork MWU 则连带 AGPL-3.0 | GPL/AGPL 传染，自用无碍 |
| 维护/迭代成本 | 最低，一套语言一个进程 | 中：跨进程调试、前后端两套 | 高：受制于上游 UI 的路线（MXU 明说拒绝小众功能） |

## 推荐与理由

**路线 A：PySide6 + QFluentWidgets 自建。**

- MFW-CFA 证明了这条路在 MaaFW 生态完全走得通（同是"maa 绑定 + Python + PySide6"，它只是把界面做成了通用启动器；我们做专用界面，难度只低不高）。
- 外观直接对齐 MAA 系的 Fluent 风（左导航 + 任务 + 日志 + 截图），符合"正经 UI"的预期；深色主题、中文字体现成。
- 全程 Python 单栈：`gui.py` 从 tkinter 重写为 PySide6，`runner` 接口不动；后续决策流面板把 agent 的 log 从纯文本升级成结构化事件（step/action/thought/frame）即可。
- 布局参考 MAA 本体：左侧导航栏（任务 / 探索录制 / 知识与剧本 / 运行记录 / 设置）+ 右侧主区，截图预览常驻侧栏。

**保留选项 B**：如果将来决策流可视化对排版的要求超出 Qt 能忍的程度（自由画布、逐帧 diff 查看器之类），再上 FastAPI + Web，或 fork MWU 改造——迁移点只在"壳"，核心代码不变。

**排除 C**，理由见上；若未来发布给他人，再评估 PI V2 化。
