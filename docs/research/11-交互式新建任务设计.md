# 11 · 交互式新建任务（教学模式）设计

> 2026-08-29 ｜ 用户提议，讨论定稿 ｜ 状态：设计已对齐，待实施

## 0. 一句话

GUI 新增"新建任务"会话页：上半实时游戏画面、下半聊天。用户口述任务目标 → 模型从主界面导航并操作，拿不准就停下提问 → 用户答复后继续 → 用户宣布完成后蒸馏产出**任务三件套**（daily.yaml 条目 + flow 剧本 + 知识卡），入库 shadow 走既有保险期转正。

## 1. 动机：补意图传递的短板

现有 `explore` 是纯自主探索：新任务的意图只能压进一段 prompt，模型靠猜，猜错烧步数甚至产出退化剧本（见 09 的 degenerate 拦截）。教学模式把"猜"变成"问"：

- 意图在模型需要的时刻精准注入，提问**必须附猜测选项**（"我猜该点右边这个，对吗？"），用户确认成本极低；
- 副产品价值更高：聊天记录本身就是任务规格——蒸馏时用户的话（含纠正、日文词、坑位描述）转成新任务的 prompt / exit_condition / 注意事项，质量远高于一行 prompt，未来 LLM 兜底接管时也受益。

## 2. 交互流程与状态机

```
新建会话（任务名 + 一句目标 + 可选的入口提示）
  → AUTO     模型自主导航/操作（全程录制：前帧+坐标+eff）
  → AWAITING 拿不准 → ask_user 挂起（画面预览继续动）
  → AUTO     用户答复（可多轮）→ bring_to_front → 继续
  → MANUAL   随时：用户手动接管 / 禁区降级（见 §5）
  → 用户点「完成」→ DISTILLING → 入库 shadow → DONE
```

蒸馏（离线，不实时维护剧本）：`select_flow_steps` 挑最短正确路径 → `flowgen` 生成 yaml+锚点 → `summarize_session` 由会话+轨迹生成任务卡 → 三件套落盘。用户在 GUI 预览生成的剧本（只读 + 重新生成即可，V1 不做编辑器）。

## 3. 已定决策（2026-08-29 与用户确认）

| 分叉 | 决策 | 理由 |
| --- | --- | --- |
| 教学范围 | **全程教学**：入口导航也录进剧本 | 回放全自动；途经抽卡/亲密度禁区段时降级"用户手动开+录制暂停" |
| 提问尺度 | **不确定就问** | 教学期轨迹质量优先，试错留给 shadow 期；每问必须带猜测 |
| 完成验证 | **事后验证**：入库即 shadow | 贴合 09 的升降级机制——下一次任何执行（次日日常自动跑，或手动跑）都算保险期验证，连续 2~3 次成功转正，不打断当下 |
| 手动接管 | **V1 就要** | 暂停录制→手动操作→恢复；与禁区降级共用同一机制 |

## 4. 组件改动清单

| 模块 | 改动 |
| --- | --- |
| `brain.py` | 教学版 system prompt（**继承**禁区/消费红线/弹窗规则）+ `ask_user` 动作；report 仅用于 blocked（完成由用户宣布）；新增 `summarize_session`：会话+轨迹 → 任务卡 |
| `agent.py`/`runner.py` | `interactive_session()` 状态机；复用 record 钩子；看门狗触发从"中止"改为"挂起提问"；用户消息全量入轨迹；`queue.Queue` 双向通道（现有信号全单向） |
| `gui.py` | 第三页"新建任务"：预览 + 消息流（模型动作以卡片混排，改造复用 StepCard）+ 输入框 + 完成按钮；任务列表在教学完成后重载（`_fill_tasks` 目前只在启动时读） |
| 预览源 | 独立 5~10fps 截图线程（`frame_cb` 目前每步一帧，挂起时画面不动）；游戏窗口保持前台，预览是**镜像**不是嵌入（10 号文档已论证嵌入路线不通） |

## 5. 手动接管与禁区降级（同一机制）

- **普通接管**：接管期间继续记录帧序列（无点击坐标——用户点的是真鼠标，采不到）。恢复后模型看首尾帧 + 问一句"刚才做了什么"，答案作为文本步骤入轨迹；蒸馏时据此为该段生成步骤，锚点取自动作发生时刻的帧。
- **禁区段**（抽卡/亲密度）：**完全停截图**（不只是停录制），用户手动开过去，恢复点以"恢复后的第一帧"为锚点继续。铁律不变：入档画面必须安全（见 [[dotabyss-nsfw-no-go-zones]]）。

## 6. 技术注意点与风险

- **焦点时序**：输入靠前台 Seize 点击（Unity 旧 Input 不读消息队列），用户打字必抢焦点——但打字只发生在 AWAITING_USER，天然无冲突；恢复行动前重新 `bring_to_front` 即可。
- **上下文**：沿用"图像不进历史 + 文本滑窗 `HISTORY_KEEP`"，但**用户消息全量保留**（它们是规格的一部分）。
- 手动接管段的回放缺口：帧序列+一句口述未必能完整还原多步操作——蒸馏时该段步骤标低置信，shadow 保险期重点观察，失败自动回 LLM 兜底（机制已有）。
- ask 频率：prompt 约束"仅当画面与已有指示都无法确定下一步时提问"；教学会话是一次性成本，时延不敏感。

## 7. 实施顺序（建议）

1. `ask_user` + 教学版 prompt + reply queue（runner 可先用 CLI 跑通状态机）；
2. GUI 会话页（预览线程 + 聊天流 + 输入框）；
3. 蒸馏接线（flowgen 已有，补 `summarize_session`）+ 任务列表刷新；
4. 手动接管 / 禁区降级；
5. 用一个真实新任务走全程，验证 shadow→转正闭环。
